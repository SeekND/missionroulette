⚑ Set up your org's shared campaign

One shared war room for your whole org — same map, same treasury, same chronicle, everyone on their own device. Your campaign lives in your org's own free database: this site hosts nothing and can see nothing. Setup takes about ten minutes, once, by one person — you.

1Create a free Firebase project

  1. Go to console.firebase.google.com and sign in with any Google account.
  2. Create a project — name it anything (e.g. your org's tag). You can switch Google Analytics off.

Firebase's free tier is far more than a campaign needs — a whole season is a few thousand tiny entries. No credit card involved.

2Turn on anonymous sign-in

  1. In the left menu: Security → Authentication (on the older console: Build → Authentication), then Get started.
  2. Under Sign-in method, choose Anonymous and enable it.

Nobody creates accounts or passwords — this just lets the database tell "someone with the join code" from "the open internet".

3Create the database

  1. In the left menu: Databases and storage → Realtime Database — it's in the NoSQL group, next to Firestore (older console: Build → Realtime Database). Careful: Realtime Database, not Firestore.
  2. Press Create database. Any location; start in locked mode.
  3. Open the Rules tab, replace everything with the block below, and press Publish.
{ "rules": { ".read": false, ".write": false, "campaigns": { "$campaign": { "events": { ".read": "auth != null", "$event": { ".write": "auth != null && !data.exists()", ".validate": "newData.hasChildren(['t','a','k']) && newData.child('t').isNumber() && newData.child('a').isString() && newData.child('k').isString()" } }, "reports": { ".read": "auth != null", "$day": { ".write": "auth != null && !data.exists()" } } } } } }

These rules make the campaign append-only: entries can be added, never edited or deleted — the war log can grow, but nobody can rewrite history. The reports block lets the board post each day's battle report to your Discord exactly once.

Already running a campaign from before? Paste these rules again and press Publish — the reports block is new; nothing else changes.

4Register a web app & paste its config here

  1. Easiest: on the Project Overview page, press + Add app and choose </> (Web). (Also under Settings → Project settings → General → Your apps.)
  2. Register it (any nickname, no hosting needed) and copy the firebaseConfig block it shows.
  3. Paste the whole thing below — formatting doesn't matter. Do step 3 first — the config only includes the databaseURL once the database exists.
Your org's join code

Share the code in your org's Discord. Members open the Org Campaign page, scroll to "Playing with your org?", and paste it — that's their whole setup. First person in creates the campaign.

Good to know

What does it cost?
Nothing, realistically. A full season is a few thousand small entries — a rounding error inside Firebase's free tier.
Who can see our campaign?
Only people with the join code. This site never sees it at all: your board talks straight to your org's own database.
The code leaked — now what?
Come back here, paste the same config, and generate a fresh code — it points at a brand-new campaign path. Share the new one, and the old one goes stale.
Can we run a second campaign?
Yes — every generated code gets its own path in the same project. One database can hold every season you'll ever run.
Backups?
The war room's export log button downloads the entire campaign as a file, any time, from any member.
